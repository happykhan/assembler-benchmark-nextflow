What the benchmark measures

Revised baseline: plasmids ≥20 kb

S1 includes chromosome-only controls and chromosome/plasmid inputs where every plasmid is at least 20,000 bp. S2 requires larger-plasmid coverage controls; S3 requires repeated frozen larger-plasmid inputs. Smaller plasmids belong in the dedicated S4 challenge. Historical mixed-size S1–S3 runs remain supplementary, with their original scores and detailed evidence.

The current saved data support chromosome-only and single larger-plasmid S1 controls. The multiple-larger-plasmid S1, revised S2 and revised S3 panels are not assessed. No replacement references or new computations were introduced by this reporting change. Archived batch summaries retain their original counting scope. The execution profiles described below are historical.

Known molecules, controlled reads and a visible scoring rule. The first pilot asks whether tools recover plasmids correctly when there are no read-sequence errors.

The next stages

The S1/S2 profile expands the baseline to five pinned references: E. coli MG1655, W and SE11, and K. pneumoniae Ecl8 and MGH 78578. S1 contains 22 chromosome-only, single-plasmid and native-complement scenarios. S2 adds ten small-plasmid scenarios: W pRK2 and MGH 78578 pKPN7, each at 0.8×, 1×, 1.2×, 3× and 5× relative depth. Chromosome depth stays at 30×. Read properties and the per-accession simulation seed remain fixed.

That produces 128 comparisons across four tool configurations. Jobs run with four threads each and at most four assembler tasks concurrently. The 1× coverage cases deliberately repeat baseline input conditions as controls; they are not independent biological samples or the planned determinism experiment. S3 repeat/thread testing and S4 read-length challenges run in separate batches, shown in the scenario results.

From references to reads

The pilot uses the pinned University of Florida E. coli W assembly, GCF_000258145.1. Preparation retrieves each exact RefSeq accession, checks its length and ACGT alphabet, and records file and sequence checksums. Those checks establish reproducible sequence inputs; they do not independently validate the underlying biological assembly.

A Python sampler chooses random starts, both strands and lognormally distributed read lengths. Circular reads can cross the reference's arbitrary start coordinate, but are capped at one circumference. The sampler records every read's source coordinate, strand and length. Sequencing errors, adapters, chimeras and extraction/library bias are absent. This is an idealised long-read baseline, not realistic nanopore chemistry.

The initial targets are 30× chromosome depth and equal per-base plasmid depth, a 10 kb mean/5 kb SD before clipping, and 500–50,000 bp length bounds. Small molecules are capped further, so their achieved length distribution differs. Sampling ends after reaching the target, permitting one read of overshoot per molecule. The pages report achieved depth and breadth. Q40 is a FASTQ placeholder, not calibrated uncertainty.

Exact sequence recovery

A plasmid passes when exactly one output contig matches the complete truth molecule, allowing a circular rotation or reverse complement. Duplicate exact molecules and identifiable extra full copies fail unique recovery. A tandem-expanded plasmid does not qualify as an exact dedicated molecule. Each plasmid-containing scenario passes only when every expected plasmid passes. Chromosome recovery is recorded separately.

For the chromosome-only negative control, a whole-genome assembler must return exactly the expected chromosome. Plassembler's plasmid output must be empty. These different endpoints are shown on the scenario pages; they should not be interpreted as identical chromosome-assembly tests.

The first evaluator does not classify partial recovery, general false joins, repeat collapse or topology claims. A missing exact match means “no exact dedicated molecule”, not proof that the plasmid was entirely absent. Unclassified extra contigs remain visible and are not automatically labelled plasmids. Supplementary alignment evidence is reported separately when available; it never changes this strict sequence endpoint.

Reading the table

Pass and fail mean a completed sequence assessment. Not run, queued and running do not contribute to those counts. Job errors, resource failures and invalid inputs remain separate unscored outcomes. A website build never invents missing results.

Each report is a snapshot of one batch and its configuration, not a live view of the cluster. A single execution is not a determinism experiment. Repeated executions, thread sensitivity, independent simulation seeds and realistic nanopore errors will be separate panels.

A batch-specific collector can refresh the published snapshot as jobs progress. It checks Slurm once a minute, publishes changed results at most every ten minutes, and publishes the final state on completion. It stops after its configured time limit. Earlier batches remain available from the navigation.

Repeated executions and thread sensitivity (S3)

Two frozen read sets (W/pRK2 and MGH78578/pKPN7) are reused for five executions per tool at one and four tool threads: 80 executions. Each task reserves four Slurm CPUs; the tool thread count and reservation are recorded separately. Byte identity, normalised sequences and strict biological outcomes are compared within and across thread settings. Normalisation ignores names, ordering and reverse-complement orientation; circular rotation is ignored only for exact truth-matched circles. Non-exact contig ends remain meaningful. Duplicate sequences remain represented. Missing, errored or unequal-input repeats cannot establish agreement. S3 headlines output agreement independently of recovery. This batch uses default mode only. A separate profile adds Flye’s --deterministic flag at both thread counts; it has no measured results yet. The flag makes initial disjointig assembly single-threaded and is tested rather than assumed to guarantee determinism.

Small plasmids and read length (S4)

W/pRK2 (5,360 bp) and MGH78578/pKPN7 (3,478 bp) are assessed individually with their chromosome and within the native complement. Whole-input length targets are short (mean 1.5 kb, SD 0.5 kb, bounds 0.5–2.5 kb), baseline (10 kb/5 kb, bounds 0.5–50 kb) and long (25 kb/10 kb, bounds 0.5–100 kb): 12 scenarios and 48 comparisons. Every molecule remains capped to one circumference; the chromosome distribution changes too. These cases test the declared sampler and assembler response, not library retention or size-selection losses. The achieved per-molecule read count and length range are shown. No admitted reference in this panel is below 2 kb.

Supplementary recovery evidence

A separate Slurm step maps saved assemblies to their frozen truth with minimap2 asm5 and base-alignment CIGAR output. The retained mapping policy requires mapQ ≥20, alignment identity ≥90% and at least 200 aligned reference bases. Secondary mappings, ambiguous-base alignments and unknown mapQ are excluded. Reference coverage unions aligned blocks without counting deletions as recovered bases. Identity is alignment-weighted and can count overlapping alignments repeatedly; no accepted alignment leaves identity unestimated. Fragmentation, duplication and joins are candidate evidence under explicit thresholds, not confirmed structural errors or topology claims. Shared repeats, short alignments and circular-origin splits can be missed.

Diagnostic evidence records mapper version, policy and input/assembly hashes, and is attached only to the matching execution. Older execution records may lack input hashes; retrospective diagnostics verify the frozen input manifest and expose that limitation. Runtime source hashes are recorded for newly launched executions as source evolves; each batch also retains its preparation source snapshot.

Graph and contig lengths

Every result has separate graph-segment and scored-output length inventories, with count, total, shortest, median, longest, N50 and N90 where complete metadata exist. Raw graph totals count segments once and do not subtract link overlaps or account for repeated path traversals; they need not equal final contig totals. Source roles distinguish final output from retained intermediate graphs.

N50 and N90 use descending cumulative base counts, not record percentiles. These are length statistics, not sequence-correctness or plasmid-recovery scores. Missing inventories and unknown lengths remain unmeasured. The standalone backend download includes the same measurements in JSON and TSV.

Linear-plasmid controls (S5)

The first S5 profile uses isolated SCP1 and SLP2 reference records, without a chromosome or a native-complement claim. Standard and repeat-spanning read conditions are kept separate. The versioned linear simulator adds two declared terminal reads per end, retains physical boundaries and requires complete input breadth. This is an ideal-data control, not a model of terminal protein chemistry or library capture.

Linear equivalence accepts a reverse complement but not rotation. Exact sequence recovery and tool-reported topology remain separate assessments. Plassembler uses explicit no-chromosome mode, which skips its initial Flye stage; its artificial workflow placeholder is not an input reference or a biological chromosome.

Aggregate plots and dataset design

Aggregate figures use saved measurements, separating primary and supplementary cohorts. Repeatability has its own figure; repeated S3 executions are excluded from recovery/resource plots. Source tables and SVG/PNG downloads are included in the backend bundle. Input plots deduplicate saved read-hash/replicon records within each cohort.

Wick and Holt's broad benchmark varied reference genomes and read properties; ours is currently a small diagnostic suite dominated by exact-read controls. A general evaluation track should follow those broad design principles while targeted plasmid challenges retain matched controls. Dataset generation is unchanged in this reporting update.
